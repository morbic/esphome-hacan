= HACAN-ADR-0006: Use active bridges and one global address space

Status: *Proposed*

== Context

Building wiring may require branches, while passive CAN stars create signal
integrity problems. Devices on downstream branches must still communicate with
controllers and peers without encoding physical paths in every binding.

== Considered options

* Passive branches: no forwarding code, but topology and stub length become
  electrically unsafe at useful scale.
* Per-segment address domains with translation: scalable, but complicates
  identity, diagnostics, and peer bindings.
* Global addresses with active forwarding: simple application identity, with
  route tables and duplicate suppression in bridges.

== Decision

Branches are separate CAN segments joined by active store-and-forward bridges
in a logical tree. All segments share one address space. Bridges learn routes,
increment a hop field, bound queues, and suppress recent duplicates.

== Consequences

Each segment can be correctly terminated and may be isolated. Bridge software
is more complex and adds latency. Cyclic routed topologies are unsupported; hop
and duplicate controls contain faults but do not make cycles valid.
